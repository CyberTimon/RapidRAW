# Learning from human RapidRAW edits

Use this when a photographer returns editable RapidRAW versions of an earlier handoff. The objective is to improve the next edit, not to overwrite the returned files.

1. Inventory DNG and adjacent `.rrdata` pairs in the earlier handoff and the returned directory. Match by stable image identity and compare DNG bytes or hashes. If they differ because a DNG was re-saved, reconcile source metadata and native pixels before attributing a visual difference to the sidecar. Keep absent returns distinct from a stated rejection. Preserve both sidecars and any existing review decision.
2. Compare sidecar structure without printing embedded mask or patch data. Summarise changed crop geometry, global tone and colour, local masks and their inversion/intersection/brush refinement, lens blur, grain, and applied retouch patches. Distinguish a new mask from a changed existing mask. Treat GUI-only history entries as candidate history, not proof that every candidate is applied.
3. Render the inherited edit through a compatible native RapidRAW engine. Compare it with the actual earlier deliverable at whole-image size, then inspect the same source region at native detail for masks, texture, and repairs. Different crops need an explicit geometry comparison; a tighter crop is not automatically better. If MCP rejects a GUI sidecar field such as `inpaintHistory`, retain the original and inspect it through a compatible editor or engine. Do not strip or rewrite the sidecar merely to make the import pass. Report the limitation if the visual comparison remains unavailable.
   When the photographer also supplies JPEG or TIFF exports, associate each export with its source and sidecar using available provenance and visible content; mark any uncertain association. Verify identity, dimensions and colour profile, then use an established export as the visual record of the human edit. It can support a style comparison even when MCP cannot replay the sidecar. Keep a reduced review export distinct from a native-resolution repair or print-quality check. Publish it as a reference variant only when the photographer wants an active comparison; for a skill-only blind round, keep it in historical evidence outside the active review collection.
4. Convert the differences into operation choices for the next photograph. Decide framing from the gesture and habitat before finishing local light; masks use source coordinates even when the render is cropped. When global shadow or exposure changes flatten the scene, try separate subject and inverted-background control, then compare the same whole frame. Refine spill with brushes or intersections and inspect both sides of the boundary. If an earlier selection already covers the intended region, correct that mask before stacking another. Put sharpness where the material supports it instead of assuming global crispness helps. Use grain, vignette, blur, or cleanup only when the rendered result benefits. Compare retouch patches with the unrepaired source at native resolution before calling a cleanup successful.
5. Store image-specific evidence and any numeric settings in the private workspace. Update the personal style profile with visible relationships and counterexamples; update this skill only with reusable tool decisions. In an ordinary continuation, check the next applicable first delivery against a relevant human edit and the earlier miss. In a requested skill-only blind round, do not open those earlier images, sidecars, profiles or prior review cases before or during the first delivery; freeze that candidate, its editable state, and operation provenance before feedback, and defer retrospective comparison until the photographer requests it. Keep source selection, human revision, explicit acceptance, and book inclusion as separate states.

An import, sidecar diff, or successful render is not an artistic acceptance test. The final comparison must be visible in the photograph.
